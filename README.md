# soda-server
Please serve the soda—but be careful not to spill it.

炭酸飲料を **なるべく速く、でもこぼさずに** コップへ注ぐブラウザゲームです。
泡の立ち方は [soda_foam_physics_report.md](soda_foam_physics_report.md) の物理モデル(§9 の L1 モデル)をリアルタイムで解いて決めています。

## 起動

ビルドも依存パッケージも不要です。

- `index.html` をブラウザで直接開く、または
- `npm start`(= `node tools/serve.js 8080`)を実行して http://localhost:8080/ を開く

## 遊び方

| 操作 | 内容 |
|---|---|
| 押す位置の高さ(マウス / タッチ) | ボトルの傾き。画面の縦軸の目盛りのとおりで、0° の破線より上で出始め、上ほど勢いよく注ぐ(上の方はゴボゴボ言う全開) |
| 押す位置の左右 | グラスの傾き。画面の横軸の目盛り(0〜60°)のとおりで、右ほどボトル側へ傾き、液が内壁を伝って静かに入る |
| 離す | ボトルもグラスも元に戻る(注ぐのをやめる) |
| ホイール / 右のスライダー | 注ぎ口の高さ。高いほど液柱が速く突っ込み、空気を巻き込む |
| R / Space / 矢印キー | やり直し / 押したまま / 操作 |

ステージ全体がこの対応のグラフになっていて、押している位置(マウスなら載せた位置)には十字線が引かれ、その時の傾きがカーソルのそばに出ます。

- 液体(泡の中の液は数えない)が **目標線** に届いた時点でタイム確定。その後、泡が落ち着くまで見届けてこぼれた量を集計します。
- **記録 = タイム + こぼした液 1 mL ごとに 0.5 秒**。条件ごとのベストはブラウザ(localStorage)に保存されます。
- 右のパネルで飲み物(水 / 炭酸水 / コーラ / サイダー / ビール / シャンパン)・液温・グラス(タンブラー / ビアグラス / フルート / プラカップ)・グラスの温度と表面・氷・目標量を自由に変えられます。「詳しいパラメータ」ではガスボリューム・泡の寿命・核生成サイト密度・空気の巻き込み倍率も変えられます。
- **水(練習用)** は炭酸が入っていない操作の練習用で、選ぶとステージの下に操作の説明が出ます。記録が 1 件もないブラウザ(初めて遊ぶとき)は水で始まります。

定石は「グラスを傾けて壁を伝わせ、液が増えたら起こしていく」。ただし勢いよく注ぐと液柱が壁に届かず、直接突っ込んで泡立ちます。

## 物理モデル(js/physics.js)

計算式の詳しい解説は [physics.html](physics.html)(ゲームの右上の「物理モデル」)にあります。

| 報告書 | 実装 |
|---|---|
| §1 溶解と過飽和 | 溶解度は §1.1 の表を補間(範囲外はファントホッフ 2400 K)、糖・エタノールの塩析係数つき。**CO₂ 収支(ボトル・液柱・溶存・気泡・泡層・大気・こぼれ)の合計は機械精度で保存** |
| §2 核生成 | 壁面サイト(放出周波数 f = D·ΔC / (ρ_g r_d²))、氷の表面サイト、突入ジェットの空気巻き込み(Biń 1993: Q_air/Q = 0.04 Fr^0.28 (L/d)^0.4、ボトルの口の出口条件で評価し、突入速度 0.6〜1.4 m/s で立ち上がる閾値つき)、乱流による微小気泡核 |
| §3 温度 | 液温・グラス温度は集中定数(熱交換は厳密な指数緩和)。壁面液膜の温度は接触温度(熱浸透率の比)から、濡れてからの時間で液温へ緩和 |
| §4 気泡の成長 | 1 個ずつではなく「同じ気泡 N 個の束」を追跡し、Epstein–Plesset 型の拡散流入 + Ranz–Marshall のシャーウッド数。巻き込んだ空気泡は CO₂ 分圧 0 から始まる |
| §5 気泡の上昇 | 剛体球(Schiller–Naumann)と変形気泡(Mendelson)の小さい方。気泡群が液を引きずり上げる泡プルーム速度 (g·Q_gas/R)^(1/3) を加算 |
| §6 泡層 | 気体と液体の 2 成分。生成時のガス体積率 φ_in、泡膜の液からの脱ガス、排液、乾くほど速くなる膜破裂(1/k_c = 泡の寿命) |
| §7 液面からの逸散 | J = k_L (C_L − C_eq) A、k_L は乱れで増える |
| §8 操作 | ボトルの流量は傾けた容器の液面と口の位置から計算(満杯なら約 69° で出始め、減るほど深く傾ける)。グラスの容量は傾きで減り、いちばん低い縁からあふれる |

グラスとボトルは軸対称容器として扱い、任意の傾きでの「体積 ⇔ 液面高さ」を解析的に積分しています。

### 報告書から調整した値

- **核生成サイト密度**: 報告書は「数個〜数百個/cm²(要校正)」。静置した炭酸水が最初に毎秒 1 mL 前後のガスを出す程度になるよう、範囲の下側(洗って自然乾燥 1、布で拭いた 8、傷が多い 25 個/cm²)にしています。
- **巻き込み量・泡プルーム・乱流核の係数**(`CAL.entrainScale`、`plumeCoef`、`turbSeed`): 「コーラを直立のまま全開で注ぐとあふれる」「傾けて壁伝いに 70 mL/s ならあふれない」などの経験に合うように合わせています。
- グラス温度の影響は小さく出ます(報告書 §3.2 の「二次要因」どおり)。液温の影響は大きく出ます。

## 開発

```
npm test            # 物理エンジンの単体テスト(体積計算・CO₂ 収支・報告書の値・注ぎ方の傾向)
npm run calibrate   # 決まった注ぎ方を自動で実行し、タイム・こぼれ・泡の高さを表にする
```

`CAL='{"plumeCoef":0.4}' npm run calibrate` のように校正パラメータを一時的に上書きして比較できます。

### CI とリリース

- **PR ごと**(`.github/workflows/ci.yml`): 全 JS ファイルの構文チェックと `npm test`。
- **`v` で始まるタグの push**(`.github/workflows/release.yml`): `npm test` が通れば、`index.html`・`physics.html`・`css/`・`js/` だけを GitHub Pages に公開します。

タグを付ける前に CHANGELOG.md や package.json のバージョンをそろえる必要があるので、公開は [RELEASING.md](RELEASING.md) の手順で行います(初回に必要な GitHub の設定も載せています)。変更履歴は [CHANGELOG.md](CHANGELOG.md) にあります。

### ファイル構成

| `tools/` | 静的サーバー、校正スクリプト、テスト用の自動プレイヤー |
